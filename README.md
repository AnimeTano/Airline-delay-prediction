# Airline Delay Prediction

Проект по машинному обучению для прогнозирования, будет ли месяц **проблемным** для конкретной авиакомпании в определённом аэропорту на основе исторической статистики рейсов

---

# Цель проекта

Основная цель проекта — построить модель бинарной классификации, способную заранее определить вероятность возникновения большого количества задержек рейсов.

Подобная модель может использоваться авиакомпаниями для:

- планирования резервных экипажей и воздушных судов;
- оценки операционных рисков;
- оптимизации расписания;
- снижения финансовых потерь и компенсационных выплат пассажирам.

---

# Данные

Источник данных:

**Airline Delay Dataset (Kaggle)[https://www.kaggle.com/datasets/sriharshaeedala/airline-delay/data]**

Период наблюдений:
- **2013–2023**

Размер датасета:
- **171 223 наблюдения**
- **21 исходный признак**

Каждая строка представляет собой агрегированную статистику:

- авиакомпания;
- аэропорт;
- месяц;
- количество прибывших рейсов;
- количество задержек;
- причины задержек;
- отменённые и перенаправленные рейсы.

---

# Постановка задачи

Решается задача **бинарной классификации**.

Целевая переменная:

```
bad_month
```

Месяц считается **проблемным**, если доля задержанных рейсов превышает **20%**.

Формула:

```
bad_month = arr_del15 / arr_flights > 20%
```

Классы:

- **0** — обычный месяц
- **1** — проблемный месяц

В ходе исследования были выполнены:

- анализ пропусков и качества данных;
- исследование распределения целевой переменной;
- анализ авиакомпаний;
- анализ аэропортов;
- анализ сезонности;
- анализ изменения ситуации по годам;
- анализ причин задержек;
- исследование влияния загруженности аэропортов;
- анализ корреляций признаков.

### Основные выводы

- Наиболее проблемные месяцы:
  - июнь;
  - июль;
  - декабрь.

- Наименее проблемные:
  - сентябрь;
  - октябрь;
  - ноябрь.

- После 2020 года наблюдается рост доли проблемных месяцев.

- Более загруженные аэропорты чаще имеют проблемные месяцы.

- Основные причины задержек:
  - позднее прибытие воздушного судна;
  - проблемы National Airspace System (NAS);
  - задержки по вине авиакомпании.

- Числовые признаки обладают слабой линейной связью с целевой переменной. Наибольшую информативность показывают категориальные признаки.

# Feature Engineering

В проекте были реализованы следующие признаки:

- циклическое кодирование месяца (`sin`, `cos`);
- признак сезона;
- лаговые признаки;
- скользящие средние (Rolling Mean);
- Target Encoding для категориальных признаков;
- стандартизация числовых признаков.

Особое внимание было уделено предотвращению **Data Leakage**.

Все лаговые и rolling-признаки рассчитываются **только по предыдущим месяцам**.

# Используемые модели

В качестве моделей были использованы:

- Logistic Regression (Baseline)
- Random Forest
- XGBoost

Основная метрика качества:

- **ROC-AUC**

Дополнительно рассчитывались:

- Precision
- Recall
- F1-score

|---------|---------:|
| Logistic Regression | **0.724** |
| Random Forest | **0.758** |
| XGBoost | **0.792** |

Лучшей моделью оказался **XGBoost**.

Результат на тестовой выборке:

**ROC-AUC = 0.767**
